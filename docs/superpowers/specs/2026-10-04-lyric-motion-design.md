# UNFOLD かんたん歌詞MV：曲・歌詞・テキストモーション

2026-10-04 / 設計確認用。方向性はユーザー了承済み。製品コードは未変更。

## 目的と成功条件

現在の「05 歌詞MV」は使い方が難しく、ユーザーは使っていない。歌詞を3D形状にする方式は新しい制作画面から廃止し、参考にしたリリックビデオ制作ツールの「歌詞・曲」「おまかせ」「気になる行だけ直す」を参考に、背景のUNFOLD映像へ独立した2Dテキストモーションを重ねる。

曲と歌詞を入れ、文字の動く見本をすぐ確認できる。歌詞に含まれる【サビ】等を演出に使う。音楽に歌詞が埋め込まれていれば入力を省く。基本操作にはBPM、拍、シェーダー、3D文字の理解を必要としない。

今回の入口はシーケンスの歌詞MVタブ。既存の1枚モード／シーケンスの回転・カメラ・画像変形は維持する。文字の計算と描画は共通モジュールに分け、1枚モードでも再利用できる構成にする。1枚モードへ音楽・歌詞編集画面を追加することは今回の対象外。

## 採用する構成と比較

1. **採用：既存の背景描画に独立した文字レイヤーを追加。** 曲・歌詞の画面は整理し、背景のカメラや崩れ方を維持できる。プレビューと出力で同じ描画を使う。
2. 既存の歌詞カードだけを改良する案：変更は小さいが、歌詞を変えると背景シーケンスまで組み直される構造が残るため採用しない。
3. 参考ツール全体を組み込む案：二つの編集・保存・出力機構の整合が必要になり、操作も複雑になるため採用しない。操作の考え方を参考にした独自実装とする。

## 画面と操作

タブ名は「05 歌詞・曲」。基本画面は次の4段階。必要な情報が揃っている段階は完了表示する。

1. **曲を入れる**：ドロップ／ファイル選択、曲名、長さ、再生・停止。既存の素材パネルで読み込んだ曲も同じ状態を表示する。
2. **歌詞を入れる**：貼り付け、埋め込み歌詞の反映、LRC/JSON読み込み。反映ボタンを毎回押さずに下書き保存し、構成見出しを色付きラベルで確認できる。
3. **おまかせで見てみる**：「読みやすく」「ポップ」「しっとり」の3スタイル。選択時に文字の配置・動き・強調色を割り当て、すぐ再生できる。未同期なら「仮タイミング」と明示する。
4. **曲に合わせて仕上げる**：大きな「今この歌詞」ボタンで行頭を記録。歌詞行と間奏開始を順に表示し、1つ戻る・途中で止める・続きから再開に対応。完成後は曲付き動画保存へ進む。

行を選ぶと「この行だけ変更」「前へ／後ろへ0.1秒」「この演出を固定」「サビ等の区分変更」を出す。スタイル再抽選は固定行を維持する。文字色・サイズ・位置・書体・モーション速度、BPM手動修正、歌詞全体の時刻移動は「こだわり設定」に置く。

歌詞のタイミング変更は背景のカットを動かさない。旧「歌詞と画像を連動」は新方式では無効にし、新歌詞の操作と混同させない。

## 埋め込み歌詞の読み取り

曲を選んだとき、音声デコードと別にファイルのメタデータをローカルで読む。歌詞の抽出失敗は音楽の読み込み成功を取り消さない。

初期対応：

- MP3 ID3v2.3/v2.4：USLT（文章）、SYLT（時刻付き）。ID3v2.2 ULT/SLTも同じ正規化結果に変換する。
- M4A/MP4：一般的な歌詞項目 ©lyr。内容がLRCなら時刻も読む。
- 外部ファイル：既存LRCとJSON、普通のTXTを維持／追加。FLAC/Vorbisや特殊な独自タグは今回の抽出対象外。音楽自体の再生可否とは分けて表示する。

時刻付きデータを優先し、文章のみのデータも候補として保持。複数言語・複数歌詞は言語／説明の選択肢を出す。欄が空なら自動反映。入力済みなら「ファイル内に歌詞が見つかりました／この歌詞を使う」を出し、クリック時のみ置き換える。Undo可能。曲を素早く切り替えても古い抽出結果を新しい曲へ反映しない。

SYLTの時刻単位がミリ秒なら直接変換。MPEGフレーム単位なら音声フレームを走査して時間へ変換する。壊れたデータ等で変換不能なら文章だけ反映し、同期済みと表示しない。改行のない単語単位データは句読点・長さで表示単位を組み、元の単語時刻を保持する。

タグサイズ・フレーム長・エンコードを検証して読み取り範囲を制限する。巨大タグや未対応圧縮フレームでは対象を読み飛ばし、固まらずに文章入力へ進める。元の音楽ファイルは書き換えない。音楽・歌詞・画像を外部サービスへ送信しない。

## SUNO等から貼った構成見出し

単独行にある既知の見出しを認識する：【】、[]、［］。英語は大文字小文字を区別せず、Chorus 2などの番号を認識する。文中の括弧は歌詞として維持する。

| 見出しの例 | 区分 | 初期の演出 |
|---|---|---|
| Intro / イントロ / 前奏 | intro | 文字なし。曲名は任意で表示 |
| Verse / Verse 1 / Aメロ / Bメロ | verse | 読みやすいスライド・フェード |
| Pre-Chorus / サビ前 | prechorus | 徐々に動きを強める |
| Chorus / サビ / ラスサビ / Final Chorus | chorus | ポップ・強調色・大きめの文字 |
| Bridge / ブリッジ / Cメロ | bridge | 落ち着いた演出へ切り替え |
| Instrumental / Interlude / 間奏 / Solo | instrumental | 歌詞を表示しない |
| Outro / アウトロ / 後奏 | outro | 動きを落ち着かせて終了 |

見出し文字は出力映像に表示しない。適用範囲は次の見出しまで。原文と見出しの順序は必ず保存する。イントロ／アウトロに歌詞が続く場合は、その歌詞を消さず区分に合う控えめな動きで表示する。Instrumentalの下に文章がある場合は矛盾として示し、「歌詞として使う」か「指示として扱う」を行単位で選べる。

未知の見出し（[Whispered]、【息をひそめて】など）は「未分類」のラベルで保持し、出力前に「表示する歌詞／演出指示」の選択を求める。通常の歌詞中の括弧、歌詞の全行を括弧で囲った場合を一括削除しない。見出しから正確な秒数・歌唱位置を推測したとは扱わない。

通常改行＝次の歌詞行、行内の / ＝画面内改行、*語句*＝強調を受け付け、対応する補助ボタンも用意する。原文は保持し、記号が不完全なら文字として扱う。

## 時刻と間奏の扱い

- 内部の歌詞時刻は「曲の先頭からの秒数」に統一。プレビュー時の曲時刻は既存仕様どおり `映像時刻 + seq.offset`。動画の音声切り出しと同じ基準で描画する。
- 信頼できる埋め込み時刻／LRC／JSONはそのまま利用。テンポ検出は文字の動きのリズムに使い、歌詞時刻を勝手に拍へ移動しない。
- 時刻なし：全体の長さへ表示イベントを均等に仮配置。間奏開始も1イベントとして数える。「仮タイミング」を表示し、実際の歌声に同期したとは表現しない。曲が未入力なら12秒の見本用時間で確認可能。
- 同期操作では歌詞行とInstrumental等の無音文字区間の開始を記録する。区間境界により直前の歌詞を終了し、次の歌詞が始まるまで表示しない。Introは初期0秒、最後のOutroは曲末まで。境界が未入力なら仮配置のままと明示する。
- 明示的な終了時刻がある行は尊重。終了時刻なしの歌詞は次イベントまで、最大6秒（詳細で変更可能）。長い空白を「間奏」と断定したりカウントダウンを自動追加したりしない。
- 時刻が逆転、曲の範囲外、重複している場合は該当行を示す。時刻が同じ単語群は同じ表示単位へまとめ、明示行同士の衝突は修正対象として示す。
- 曲付きモードの尺は原則「曲末 − offset」。背景が短ければ最後の画像を保持、長ければ曲末までを出力する。背景のカット・回転・カメラ設定自体は変更しない。「現在の映像尺を使う」も詳細で選択できる。

## テキストの見た目

初期の基本モーションはフェード＋浮上、方向指定スライド、文字ごとの順次表示、ポップ、語句の拡大強調。日本語の結合文字・絵文字を途中で分割せず、画面サイズに合わせて自動改行・縮小し、長い歌詞も表示範囲に収める。

背景は既存UNFOLDの3D映像。文字は画面上の独立した2Dレイヤーなのでカメラの回り込み、遠近感、背景のグリッチ等では歪まない。中央／下部の配置、強調語句の色、必要な文字の影を設定する。初期値は下部・読みやすさ優先。サビはスタイルを共有し、同じ演出を繰り返せる。

アニメーションは保存したseed・区間・正確な再生秒から決定する。再生回数やフレームの処理速度で変わらず、シーク・プレビュー・出力が同じ見た目になる。おまかせは歌詞レイヤーだけ変更し、背景や曲時刻は変更しない。

## モジュールと接続点

- `audio-lyrics.js`：タグ読み取り・候補の正規化。DOMに依存しない。
- `lyric-document.js`：原文、見出し、歌詞、区間、強調語句の構造化と検証。
- `lyric-timing.js`：仮配置、インポート時刻、同期操作、表示区間解決。
- `lyric-motion.js`：各スタイル・モーションの時刻依存計算。純粋関数。
- `lyric-overlay.js`：文字を透過Canvasに描き、Three.jsの専用正射影シーンで背景の後に重ねる。毎フレーム時刻に応じて更新し、出力解像度・ピクセル比へ追従する。
- `lyric-controls.js` と対応CSS：4段階の画面と行ごとの編集。
- `sequence.js`：loadAudioから抽出を呼ぶ。renderAtでSceneBlur後に歌詞を合成。空の背景でもclear後に文字を描画できるよう早期returnを調整する。既存のseq-canvasをそのまま動画エンコーダへ渡す。
- `project.js`／snapshot・restore：新ドキュメント、演出seed、ロック、時刻出所、原文を含めて保存・Undo/Redo。テンポや曲置換も履歴と整合させる。
- `timeline.js`：歌詞行と構成区間を表示し、既存画像編集と独立してドラッグ・シーク可能にする。

文字のないフレームではオーバーレイ処理を飛ばす。描画時のautoClear・描画先・viewport等は元へ戻し、背景描画へ状態を漏らさない。日本語フォントは既存のロード機構を使い、書き出し開始前に必要フォントを待つ。

## 保存互換と旧歌詞MV

新データはバージョン付き `lyricDocument` とし、プロジェクトJSONはversion 3を使用。既存のversion 1/2、custom methods、shot設定を維持する。新ファイルを旧版で読み込むと歌詞を再現できないため、保存時の形式説明に明記する。

旧3D歌詞の制作ボタンは新画面から除く。既存の旧プロジェクトは勝手に書き換えず、従来描画で開ける互換経路を残す。「テキストモーション版を作る」を押した場合のみ別名保存を案内し、旧歌詞時刻を新ドキュメントへ変換。旧歌詞カードはその背景画像へ置き換え、旧歌詞由来の3D文字トランジションを立体化なしへ変更する。画像のないカードは背景色へ変換する。元データの上書きは行わない。変換結果はUndo可能。

## エラーと手戻り

曲に歌詞がなくても貼り付けへ進める。音声が読めなければファイル名と対応不可を表示。未同期でも見本作成を可能にし、書き出し前に未同期箇所をまとめて表示する。ブラウザが曲付きMP4を作れない場合、音なし動画を完成扱いにせず、WebMなどの利用可能な代替を提示する。

曲を再読み込みしてもユーザーが修正した歌詞・時刻を自動で消さない。保存プロジェクトからの音声復元ではメタデータを再適用せず、保存ドキュメントを優先する。

## 検証・完了条件

1. 人工のMP3タグ・M4Aメタデータで、通常歌詞、時刻付き、UTF-16/UTF-8、日本語、複数候補、破損、過大長、非対応を検証。音声読み込みと抽出を分離して失敗が波及しないことを確認。
2. 見出し各表記、番号付きサビ、未知指示、文中括弧、強調、通常改行、間奏の境界をテスト。原文の保存・復元を確認。
3. 同期済み／仮配置、曲offset、途中再開、Undo/Redo、再抽選と固定、曲置換競合を検証。
4. 新旧 `.unfold` と自動保存を往復し、旧作品・回転・カメラ・自作メソッドが保持されることを確認。
5. 実Chromeで曲→歌詞→おまかせ→同期→出力を通す。文字が画像ゼロ・1枚・複数枚でも表示され、長い日本語や縦横比変更に対応することを確認。
6. 720pと1080pの音声付きMP4を出力し、音声トラック、長さ、歌詞境界、プレビューと出力の代表フレームを検証。文字OFFでは従来背景と画素比較する。
7. 既存Nodeテスト全体を実行。修正後に独立コードレビューを行い、重要な指摘を解消する。
8. 操作画面・例動画・検証記録をORICO/UNFOLD/docsに保存する。外部公開は今回含めない。
