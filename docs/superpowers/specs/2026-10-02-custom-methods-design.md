# 自作メソッド（ユーザーが追加できる崩れ方）— 設計

作成日: 2026-10-02 ／ 対象: `app/`（1枚モード `index.html`・`app.js`、シーケンス `sequence.html`・`sequence.js`、`motion.js`、`project.js`）

## 目的

ユーザーが自分で書いたコードで、UNFOLD の「崩れ方（メソッド）」を追加できるようにする。GLB の追加と同じ感覚で、ブラウザに保存して、1枚モードとシーケンスの両方で使える。公開後に知らない人のコードが入ってきても、**アプリが壊れない・落ち続けない**ようにブレーキを付ける。

## 決定事項（作者と合意済み）

| 項目 | 決定 |
|---|---|
| 共有 | ファイルで渡す。最小版は `.unfold` への同梱まで。`.unfoldmethod` の単体ファイルは動画の後 |
| 制限の強さ | バランス型：ループは上限付きで許可、試し描画・見張り・クラッシュ復帰で守る |
| 進め方 | 頂点側の自作メソッド＋ブレーキ＋エディタを週末（2026-10-03/04）までに。粒の見た目（フラグメント拡張）・`@param` スライダー・`.unfoldmethod` は動画の後 |
| 構成 | メソッドごとに別シェーダー（標準29個は触らない） |
| `.unfold` | 自作メソッドを使っていないプロジェクトは version 1 のまま。使っていれば version 2（`methods` を同梱） |

## やらないこと（最小版）

- 粒の見た目（フラグメントシェーダー）を自作する機能。`look` と `params` の欄だけ確保して、空にしておく。
- `@param` スライダー、`.unfoldmethod` の単体書き出し・取り込み。
- サーバーを使った公開ギャラリー。
- 標準29個のメソッドの見た目・挙動の変更。

## アーキテクチャ

標準シェーダー（`motion.js` の `vertexShader`）に「自作メソッド1個分の差し込み口」を足し、**使うメソッドごとに別の `ShaderMaterial`** を作る。1つが壊れても、影響はそのメソッドだけで、標準メソッド用のシェーダーは変わらない。

### 差し込み口

- 頂点シェーダーの `breakAt(float m, vec2 p, float amount)` の先頭に、自作メソッド用の分岐を置く。自作メソッドの番号は **100（スロットA）と 101（スロットB）**。
- 自作→自作の切り替え（`uMethod` と `uMethod2`）には、両方を差し込んだ組み合わせ専用のマテリアルを、必要になったときに作る。組み合わせのコンパイルに失敗したら、後ろのメソッドを前と同じにして続ける（ヘルパー関数の名前がぶつかる場合などに起きる）。
- マテリアルは `uniforms` を共有する（シーケンスは `mesh.material.uniforms` を直接読んでいるため）。`mesh.material` の差し替えだけで済む。
- 組み立てたマテリアルは、メソッドの追加時・読み込み時に事前コンパイルして、再生中に止まらないようにする。

## 自作コードの形

```glsl
vec3 userMethod(vec2 p, float amount) {
  // p: 画像上の位置（画面の単位）、amount: 崩れ具合（0 で元の絵）
  // 戻り値: vec3(x, y, 奥行き z)
}
```

- 使える道具（標準メソッドと同じもの）：`hash(vec2)`、`rot(float)`、`ph(float)`、`partC()`、`cell`、`uSize`、`uTime`、`uSeed`、`uDistort`、`uStrength`、GLSL の組み込み関数。
- 粒の見た目の番号 `gKind`、`gAlpha`、`gGlow`、`gLocal` も代入できる（番号は既存の 0〜8 の範囲に切られる）。
- ヘルパー関数を定義してもよい。ただし**ループは `userMethod` の中だけ**（ヘルパーの中のループは禁止）。ヘルパーを呼んでも、ループの回数が掛け算で増えない。

## ラッパーの保証（全メソッドに共通）

ユーザーのコードが返した値は、必ずラッパーを通る。

- NaN／無限大 → 元の位置に戻す。（NaN の検出はドライバによって効かないことがある。補うのが、試し描画の「何も映っていない」警告とクラッシュ印。）
- 位置 → 各軸 −8〜8 に切る。
- 崩れ具合が 0 付近のときは、元の絵に滑らかに戻す（`smoothstep(0.0, 0.03, amount)` で混ぜる）。始まりと終わりで絵がズレない。
- `gKind` を 0〜8 に、`gAlpha` を 0〜1 に、`gGlow` を 0〜2 に、`gLocal` を 0 か 1 に切る。

## ブレーキ（5段構え）

数字は最初の値で、実測して調整する。

### 段1：書くとき（`method-guard.js`）

- 禁止：`#`（前処理）、`gl_` で始まる名前、`uniform` / `attribute` / `varying` / `in` / `out` / `layout` の宣言、`while`、`do`、`goto`、`discard`、`main`。
- `for` は「回数が数字で決まる形」だけ（例：`for (int i = 0; i < 24; i++)`）。1つあたり64回まで。入れ子を含めた全ループの最大実行回数の合計が256まで。ループは `userMethod` の中だけ。
- 長さは8,000文字まで。`vec3 userMethod(vec2, float)` が1つ必要。
- これは文字を見る簡易チェック。本当の関門は段2以降。

### 段2：追加前の試し（`method-editor.js` / `custom-method.js`）

- 本物のGPUでコンパイルして、エラー行を日本語で出す。
- 本番の約1/16の試しメッシュで、進み具合0・0.25・0.5・0.75・1を実際に描いて、各3回の中央値を測る。基準は、標準メソッドの重いものを**同じ場で測った値の4倍まで**。小さい方で超えたら、本番サイズは試さず却下。
- 描画結果が全面透明、または元の絵と全く同じなら「何も映ってない／変わってない」と警告する（保存はできる）。
- 時間は、描画後に `gl.finish()` か1ピクセルの `readPixels` で完了を待って、`performance.now()` の差を取る。

### 段3：使用中の見張り（`method-safety.js`）

- 自作メソッドを使っている間、1フレームの描画時間を測る。直近30フレームの中央値が、**基準の4倍かつ50ms以上**になったら停止する。基準＝同じ画面で標準メソッドを使っているときの中央値（取れなければ起動時に測った値）。
- 停止したら、その◆は標準の「くしゃくしゃ」で代わりに表示して、タイルに「停止中（重すぎ）」と出す。MP4の書き出し中も同じ。

### 段4：取り込み時（`.unfold` の読み込み）

- 同梱されたメソッドは、`hash` が同じものがローカルにあればそれを使う。無ければ**隔離状態**で新しいidを作り、◆の参照を付け替える。
- 隔離中の◆は「くしゃくしゃ」で代わりに表示する。画面の上にバナーを出す：「未確認のメソッドが N 個あるよ［コードを見る］［有効にする］」。
- 「有効にする」を押すと、段1と段2を通す。通ったものだけが使える。コードが変わると `hash` が変わるので、承認済みのコードを後から書き換えても、未確認に戻る。
- 形式（JSON の形・サイズの上限・version）も検査する。

### 段5：クラッシュ復帰（最後の砦）

- JS では止められない「GPUごと落ちる」ケース用。自作メソッドを使い始める前に、`localStorage` に「試用中」の印（メソッドid・時刻）を書く。30フレーム無事に描けたら消す。タブを普通に閉じるときも、`pagehide` で消す（落ちたときは `pagehide` が来ないので、印が残る）。
- 次の起動で印が残っていたら、そのメソッドを自動で隔離して「前回このメソッドで落ちたみたい」と知らせる。`webglcontextlost` も拾って、同様に隔離する。
- 限界：ブラウザごと落とす極端なコードを100%は防げない。ただし、「落ちたまま毎回落ちる」状態にはしない。

### 共通の保証

- 標準29個は別のシェーダーなので、自作が壊れても影響を受けない。
- 自作メソッドの読み込みは1個ずつ `try/catch` にして、1個ダメでもアプリは起動する。

## エディタ（`<dialog>`）

- **入口**：メソッド一覧（1枚モード・シーケンス）の最後に水色（`--added`）の「＋自作メソッド」タイルを置く。自作タイルは水色の枠で区別して、⚙メニュー（編集・複製・削除）を付ける。
- **画面**：
  - 左：コード欄（等幅、行番号、エラー行のハイライト）。
  - 右：専用の小さな canvas で、今開いている画像（無ければテスト画像）を崩す。進み具合のスライダーとループ再生。
  - 下：チェック結果（書き方・安全・試し描画 ○ms・重さ ○倍）、名前、アイコン（1文字）、保存、キャンセル。
- **書き始め**：「サンプルから」（渦・波・ばらばらを自作の形で書いたもの）と、「AIに頼むひな形をコピー」。ひな形には、入出力・使える道具・禁止事項・「ループは `userMethod` の中だけ」を書く。
- **保存ボタン**は、段1と段2が通るまで押せない。「何も映ってない」の警告だけなら押せる。
- **下書き**：試し描画の直前にコードを `localStorage` へ下書き保存する。ブラウザごと落ちても、次に開くと復元する。
- **タイルのバッジ**：「未確認」「停止中（重すぎ）」「落ちた」。クリックで理由と「もう一度試す」を出す。

## 保存・ID・プロジェクト

### ライブラリ（`method-library.js`）

IndexedDB `unfold-method-library` に1件ずつ保存する。

```js
{ id: 'cm-<uuid>',   // ローカルで固定。編集しても変わらない。◆はこれを指す
  hash: '<SHA-256>', // コードの内容。「同じコードか」「承認したままか」の判定
  name, symbol,      // 表示名と1文字のアイコン
  vertex: '<GLSL>',  // userMethod を含むコード
  look: null,        // 将来：粒の見た目のコード（最小版では空）
  params: [],        // 将来：スライダー（最小版では空）
  status: 'ok' | 'quarantined' | 'disabled' | 'crashed',
  reason: '',        // 隔離・停止の理由（画面に出す）
  createdAt }
```

- 削除すると、使っている◆は「くしゃくしゃ」に戻る（GLB と同じ）。
- `crypto.subtle`（SHA-256）は https か localhost が必要。公開サイトは https なので問題ない。

### プロジェクト（`project.js`）

- 使っている自作メソッドだけ、`json.methods` に同梱する（`{ id, hash, name, symbol, vertex, look, params }`）。version は 2。使っていなければ version 1 のまま。
- 読み込みでは `version` を見ない（今まで通り）。`methods` が無ければ空として扱う。
- 取り込みでは、`hash` が同じローカルのメソッドがあればそれを使い、無ければ隔離で新しいidを作る。◆の `method` を付け替える。古い版のアプリで version 2 を開くと、自作メソッドは使えない。

## テスト計画

### Node の単体テスト（`tools/test/`）

- `method-guard.js`：禁止ワード、`for` の形、ループの合計、長さ、`userMethod` の有無。
- `custom-method.js`：組み立てた GLSL の文字列に、ラッパー・差し込み口・スロット番号が入っていること。ヘルパー関数のループを断ること。
- `.unfold` の同梱と取り込み：`hash` が同じなら再利用、無ければ隔離、◆の参照の付け替え、version 1 の維持。

### 意地悪サンプル（`tools/test/fixtures/hostile-methods/`）

構文エラー／`while (true)`／入れ子の合計が256超の `for`／ヘルパー内のループ／`discard`／`gl_Position` への書き込み／`#define`／`uniform` の宣言／NaN（`0.0 / 0.0`）／`1e30` を返す／崩れ具合が0でも元に戻らない／上限内だけど重い反復／8,000文字超。

### ブラウザ確認

- 良いコードを追加して、プレビューとシーケンスと1枚モードで動く。
- 悪いサンプルが、それぞれ想定の段で止まる。
- 自作が失敗しても、標準29個は動く。
- `.unfold` を取り込むと、隔離で入る。「有効にする」で使える。
- 段5は「残った印」を作って開き直し、隔離されることを確認する。GPUを本当に固めるコードは、安全のため試さない。
- 既存の `.unfold`（version 1）を開いて保存し直しても、設定値が変わらない。

- `@param` スライダー（「04 見た目」の「ぐちゃぐちゃ」グループに入れる）。
- `.unfoldmethod` の単体書き出し・取り込み。

## リスク・未確認のこと

- 基準になる「標準メソッドの重いもの」は、実装時に全29個を測って決める。4倍・50ms・64回・256回・8,000文字は初期値。
- 組み合わせマテリアル（自作→自作）は、ヘルパー関数の名前がぶつかるとコンパイルに失敗する。その場合は後ろのメソッドを前と同じにして続ける。
- シェーダーのコンパイル時間は、実機で測る。長いときは追加時に「準備中」を出す。
- NaN の検出はドライバ依存（上のラッパーの保証を参照）。
- 古い版の公開サイトで version 2 の `.unfold` を開くと、自作メソッドの◆は正しく動かない。今の `importFile` は version を見ないので、拒否はされない。
