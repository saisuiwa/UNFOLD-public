# ◆ごとの「立体は前の画像のまま」（入れ替えを遅らせる）— 実施記録

2026-10-03。X版の案2（形を「次の画像」に合わせた版）を見た作者からの依頼：最初の立体化を球にして、次をドーナツにする（最初の画像は地球なので）。

## 原因

- 立体の途中（◆の46〜54%）で、絵が前の画像から次の画像に入れ替わる（`curves()` の `swap`。◆のパネルの案内文は「画像 → ぐちゃぐちゃ → 立体 → 次の画像」だが、実際の立体は前半が前の画像、後半が次の画像）。
- そのため、形を前の画像に合わせると、球が「地球 → ピンクのスプリンクル柄」に途中で変わってしまう。案2では、形を「次の画像」に合わせて逃げていたが、「地球がドーナツ形になる」と見えて不自然だった。

## 設計・実装

- ◆に `lateSwap`（本物の `true` のときだけ。ない／それ以外は今まで通り）。
- 入れ替えの曲線を、◆の 0.72〜0.80（立体が崩れ始めて、形が56%→13%のあたり）に遅らせる：`swapCurve(tr, u, curve)`（`app/fx-mix.js`。純粋な関数）。描画では、立体化する◆（`shape !== 'none'`）のときだけ `c.swap` に使う。`uSwap` は画像の選択（`texAt`）にしか使われていないので、形や粒には影響しない。
- ◆のパネル（立体化するとき）に「立体は前の画像のまま」チェック（初期値オフ。ツールチップに説明）。オンで `tr.lateSwap = true`、オフで項目ごと消す。元に戻す（⌘Z）に対応。
- 読み込み：`withCleanFx` で、`lateSwap` は本物の `true` だけ残す。
- 版番号：`sequence.js?v=52`。

## 確認（2026-10-03）

- 単体テスト 180本が全部通過（`swapCurve` の1本を追加：オフ・おかしな値は元の曲線、0.72まで0、0.8から1、途中は戻らない）。
- **変更前の版との直接比較**（同じタブ）：標準29個×4時点＋ミックス＝117点が**全部一致**＝初期値のままなら今までと同じ絵。
- オンの効き方（絵のハッシュ）：◆の0.1・0.3・0.44と0.85・0.95では同じ、0.5・0.6・0.7・0.76では違う（入れ替わりの区間だけ）。項目を消すと元と完全に同じ。
- パネル：チェックがあり、初期値オフ、オンにして⌘Zで戻る。立体化しない◆には出ない。保存ファイルに入り、読み込みで戻る（文字の `'true'` は捨てる）。
- X版の案3を作り直した（`video/出力/X版_案3_声なし.mp4`）：◆の形は、地球→球、ドーナツ→ドーナツ、りんご→りんご。3つの◆とも「絵柄を混ぜる」オフ＋「立体は前の画像のまま」オン。球は本物の地球儀のまま崩れて、ドーナツ柄の粒になり、ドーナツ柄の画像へ。ドーナツ形はスプリンクル柄のまま、りんご形は赤い皮のまま。字幕の並びも「地球になる／ドーナツになる／りんごになる」に直した。

## 追記：画像ごとの演出も、入れ替わりのタイミングに合わせる（同日・夜）

X版の案5で、りんごの画像（赤く光る画像）に「この画像だけの演出」で光のにじみを付けたところ、画像ごとの演出が次の画像へ移るタイミング（◆の35〜65%）が、「立体は前の画像のまま」の入れ替わり（72〜80%）より早く、**赤い立体（りんご）の間に発光が先に消える**ことに気づいた。

- `mixFx` に `late` を追加。`late: true`（◆が `lateSwap` かつ立体化あり）のときは、画像ごとの演出も 72〜80% で次の画像の設定へ移る。`late` なし（初期値）は今までと同じ（テスト：`late` なしと `late: false` が同じ値）。
- 単体テスト 181本が通過。版番号 `sequence.js?v=53`。変更前の `app/` は `archive/app-before-fx-late-2026-10-03/`。
