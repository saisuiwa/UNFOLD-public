# たくさんのGLBを扱う（2026-10-03）

## きっかけ
Tripo で GLB が94個になり、「GLBはどんどん増えそう」。保存できる数が8個だと入れ替えばかりになる。

## やったこと
- `MAX_SAVED_MODELS` を 8 → **100**（`app/sequence.js`）。
- 「＋ GLBを追加」を複数選択に（`sequence.html` の入力に `multiple`、`importSequenceModels(files)`）。残り枠より多く選んだときは、入る分だけ入れて知らせる。
- 一覧のスクロール（形のグリッド `max-height:340px`、GLB一覧 `max-height:260px`）。
- 8個を超えたら名前で絞り込む欄（`.shape-filter`）。
- 変更前の `app/`：`archive/app-before-many-glb-2026-10-03/`。

## ファイルの整理
`models/tripo/` をフォルダ別（動物・生き物 / 植物 / 乗り物 / 楽器・音楽 / 人物 / もの・風景 / キャラクター）に分けた。見本は `一覧.png`、使い方は `はじめに.md`。

## Tripo からの取り込み（メモ）
Tripo Studio の書き出しはブラウザの「複数ファイルのダウンロード」ブロックで落ちなくなった。ページ側で `<a download>` のクリックを横取りして、中身（blob）を手元の受け口（`127.0.0.1` の小さなHTTPサーバ）にPOSTして保存した。62個（39＋23）すべて同じ手順で取り込めた。画像のアップロードも同じ受け口から配って自動化した（受け口に `GET /img/名前.png` を足して、ページ側の JavaScript で `<input type=file>` に流し込む）。

## 1枚モードも同じに（2026-10-04）
- 保存したGLBは1枚モードとシーケンスで共有しているので、1枚モード（`app.js`）にも同じ変更を入れた：上限 8→100（`MAX_SAVED_MODELS`）、「追加した形」の一覧は高さ340pxでスクロール、9個以上で名前の絞り込み欄（`#shape-filter`）。以前は、シーケンスで増やした保存GLBが全部、1枚モードの形のボタンに並んで、とても長くなるところだった。
- 版：`app.js?v=48`、`style.css?v=9`（`index.html`）。変更前の `app/` は `archive/app-before-single-many-glb-2026-10-04/`。

## グループ（タブ）で切り替え（2026-10-04）
- 「GLBが増えるとスクロールが大変」なので、保存したGLBにグループを付けて、タブで切り替えられるようにした。
  - 保存先：GLBのメタデータ（IndexedDB `unfold-model-library` の `metadata`）の `group`（文字列。無ければ「未分類」）。データベースの版は変えていない（`saveModel` に5つ目の引数 `group` を足しただけ）。
  - `app/model-groups.js`：グループ名の整え方（20文字・制御文字なし・予約語なし）、タブの一覧（すべて／標準7つ／自分のグループ／未分類）、絞り込み、タブの描画、グループの選択欄。タブは、GLBが9個以上か、切り替える先が2つ以上あるときに出る。
  - シーケンス：◆の形メニューと右パネルの一覧に同じタブ（どちらを押しても連動）。各行にグループの選択欄。新しいGLBは、見ているタブに入る。
  - 1枚モード：「追加した形」の上にタブ。選んだGLBのグループを変える欄。
  - 見ているタブは `localStorage`（`unfold-glb-tab`）に覚える（ページをまたいで共通）。
- 確認：単体テスト 214本（新規7本）、保存GLB 54個でタブの切り替え・グループ変更・新しいグループ・GLB置き場からの追加を確認。変更前の `app/` は `archive/app-before-single-many-glb-2026-10-04/`（タブの前の状態もこの時点とほぼ同じ）。
