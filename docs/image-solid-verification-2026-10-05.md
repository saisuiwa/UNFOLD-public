# 画像JavaScriptメソッドの立体化：検証記録（2026-10-05）

既存画像片の物理軌道から選択した立体へ集まる機能を追加。GLSLとJavaScriptで共通の形状関数を使い、カスタムGLBの頂点・UVを保持する。1枚モード、シーケンス、コードエディタを接続。

## 確認済み

- 変更前310件、変更後314件のNodeテスト成功、失敗0。
- Chrome Worker実描画：異なる物理プリセットが同一の球へ収束。3→1→3秒の逆シークで画像ハッシュ一致。
- 球・ドーナツ・ハート・星・ダイヤの描画区別、両端で元画像へ完全復帰、強さ0でも立体化、奥行きと回転の反映。
- 生成したTorusKnot GLBを実際のimportModelで取り込み、4096面を保持して集合・逆シーク。転送後もホストの配列が破損しない。
- 実UI：GLB読み込み、球／ハート／GLB切替、立体化オンオフ、編集画面の「作品で選んだ形」、シーケンス共有、Undo/Redo、.unfold保存・復元。ページ例外なし。
- 両モード720p MP4（各2秒）、シーケンス1080p60＋音声の範囲書き出し（1.002667秒）、書き出し中止からの復帰。
- 既存GLSL／JSの各方向ミックス、JS同士、GLSL同士をWebM出力。未確認コードの停止、強さ0とconceal切替の回帰成功。
- 生成した100万三角形のターゲットを実GPUで準備・3→1→3秒描画。今回の計測は準備207ms、描画134/85/36ms。これは形状伝送・描画の試験であり、実GLBファイルの読み込み時間や全PCの速度保証ではない。

## 独立レビューと修正

独立レビューで重大問題なし、互換性の重要指摘2件。両方とも失敗を再現するブラウザテストを追加し、修正後に成功。修正後に314件の全テストと両モード動画・UI検証を再実行して成功。

1. 初回updateや物理イベントで追加した画像片が集合に含まれない → 画像片数が変わったときに対応を再構築。
2. 非表示の片や親Groupが集合開始時に突然現れる → 片ごとの可視性を記録し、formに合わせて徐々に完成形へ補間。

判断：非表示片はform=0の時点では見せず、form=1では選んだ立体の全体を完成させる。既存の自作演出で完全非表示を維持したい場合は立体化をオフにする必要がある。この仕様はAPI文書に明記。
