## 起動と使い方

作業フォルダで以下を実行し、http://127.0.0.1:8778/workshop.html を開きます。

```sh
python3 -m http.server 8778 --bind 127.0.0.1 --directory app
```

1. **画像の崩れ方 / 画像・立体・物理 / 文字モーション** を選択。
2. サンプルブロックをタップすると図解画像で実際の動きを表示。画像不要で開始できます。自作・取り込んだコードは開くだけでは実行しません。
3. コードを貼り付け・編集し、**プレビュー**。必要なら画像A/B、立体、物理設定、試す言葉、書体を変更。停止・再生位置・強さも操作できます。
4. 参照画像は別枠に保存。**Aにも使う**を押した場合だけ描画画像になります。パレットはHEX / JavaScript `0x` / GLSL `vec3` をコピーでき、文字色と強調色はテキストAPIに渡します。
5. 確認後、名前を付けて **UNFOLDに追加**。ダウンロードではなく既存のブラウザライブラリに保存します。
6. 1枚モード、またはシーケンスで使います。シーケンスでは対象の◆変形／歌詞を選び、届いた案内の **このブロックに使う** を押します。通知だけではプロジェクトを変更しません。適用はUndo可能です。
7. 別PC・別ブラウザへ渡す場合は `.unfoldmethod` / `.unfoldmotion` を書き出して読み込みます。下書き・参照画像・確認用サムネイルは共有ファイルに含めません。

本体ヘッダー、メソッド集、モーション集、GLB置き場から工房へ移動できます。既存の組み合わせ式文字モーションはモーション集へのリンクから利用します。

## 既存作品と下書きの保護

- 下書きは新しいlocalStorageキーに、画像は専用IndexedDBに保存。以前のコードエディタの下書きを上書きしません。
- 保存中に別のカードへ移動／追記しても、提出時の下書きだけを保存。重複保存を抑止し、現在の下書きのIDを変えません。
- 保存した画像メソッドの実行内容を編集すると**新しいIDの版**として保存。旧定義もDBに残り、既存作品・未選択ブロック・Undo・再読み込みを保護します。元の版も一覧に残ります。
- 文字モーションの既存設定（大きさ、速度、位置、方向など）は編集・共有で保持。プレビューも本体の `codeFrameInput` を使用します。
- 選択中の変形は適用を押した時点で固定し、保存データ読み込み後にも対象の存在と書き出し状態を再確認。
- 画像の連続選択／リセットは最新操作を優先。遅れて読み込まれた古い画像で戻りません。
- 容量不足・破損データをエラー表示。追加の失敗を成功扱いせず、入力済みコードを保持します。

## 構成と制限

HTML/CSS/ES Modules、既存Three.js／Troika Text／GSAP／Rapierバンドルを再利用。`workshop-data.js`（下書き・画像）、`workshop-preview.js`（描画の寿命）、`workshop-library.js`（既存保存形式）、`workshop-link.js`（明示適用）に分離。

同時プレビューは1つ。非表示・コード編集・切り替え・強制停止で破棄。表示は800×450まで。画像はPNG/JPEG/WebP、20MiB・80M画素以内、長辺2048pxへ縮小します。プレビューの文字フォント選択肢は同梱6種です。クラウド共有アカウントや投稿・同期機能は含みません。

保存は同じサイト／ブラウザ内です。ローカルポートと公開サイトは別の保存領域になります。GLSLは位置を返す方式なのでパレットで画像を自動着色しません。コード内の固定色は必要に応じてコード側を変更します。

既存のCPU ImageData経由の画像転送対策は無変更。以前報告されたChromeの間欠的なネイティブクラッシュは、本人の自作コード・プロジェクトで再現できていないため完全解決とは断定しません。今回のブラウザ検証は合成画像と既存公開モデルを隔離した保存領域で行い、ユーザー画像・コード・ダンプを外部へ送っていません。
