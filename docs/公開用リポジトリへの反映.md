# 公開用リポジトリへの反映

2026-10-17 作成。UNFOLD のソースは、次の2つに分けています。

- **本体（非公開）**：`saisuiwa/UNFOLD`。作業はすべてここ。毎日のルーティン（16:26 JST ごろ）も、Mac での作業も、ここの `main` に push します。
- **公開用**：`saisuiwa/UNFOLD-public`（2026-10-17 作成、MIT）。本体の `main` を書き換えた写し。`node tools/public_mirror.mjs --push` でだけ更新します。

写しの中身（いちばん新しいファイル）は、本体の `main` と**まったく同じ**です。書き換えるのは過去のコミットだけです：

- コミットのメールアドレスを、GitHub の noreply アドレスに
- 過去の版に残っている、Mac のユーザー名が入ったパスを `~` に、あだ名を「作者」「Claude」に、口語の発言の引用を中立な要約に
- 過去の版の、参考ツールのサンプル歌詞を、今のオリジナルの歌詞に（古い使い方の写真は写しから外す）
- `main` だけを写す（ほかのブランチや PR は持っていかない）

今のファイルがきれいなことは `tools/test/public-hygiene.test.mjs` が普段から見張っています（あだ名・`/Users/<名前>/`・個人のメールアドレス）。

## 反映のしかた（毎回、作者の OK をもらってから）

1. 毎日のルーティン（16:26 JST ごろ）と重ならない時間にする。
2. 本体の `main` が GitHub に push 済みであること（写しは GitHub の本体の `main` から作ります。この Mac のフォルダからではありません）。
3. `node tools/public_mirror.mjs` — 写しを作って調べるだけ（push しない）。次の3行が出れば準備OK：
   - `checked … clean; the files are the same as the private main`
   - `public … N new commit(s)` — 公開用に増えるコミットの数
   - `DRY RUN nothing pushed`
4. 作者に、増えるコミットの数と内容を見せて OK をもらう。
5. `node tools/public_mirror.mjs --push` — 同じ検査をもう一度してから、公開用の `main` に push します（force-push はしません）。

必要なもの：`git filter-repo`（`brew install git-filter-repo`）と、下の規則ファイル。

## 規則ファイル（`public-mirror/`。Git の外）

リポジトリの中の `public-mirror/` に置きます。`.gitignore` で除外されているので、Git にも公開用にも入りません。**中に、消したい文字そのもの（古いメールアドレスなど）が入っているので、どこにも公開しないこと。** この Mac の ORICO にだけあるので、別の場所にも控えを置いてください（失くすと、同じコミット番号の写しが作れなくなります）。

| ファイル | 中身 |
|---|---|
| `mailmap.txt` | 古いコミットのメール → noreply（`git filter-repo --mailmap` の形式） |
| `replace-text.txt` | すべての版のファイルで置き換える言葉（`--replace-text` の形式。`regex:` で正規表現） |
| `replace-message.txt` | コミットのメッセージで置き換える言葉 |
| `strip-blobs.txt` | 写しから外すファイルの版（古い使い方の写真）。1行に1つの blob id |
| `forbidden.txt` | 写しのどこにも残っていてはいけないもの（`tools/lib/public-hygiene.mjs` の決まりに加えて調べる） |
| `public-remote.txt` | 公開用リポジトリの URL（まだ無いときは、写しを作って調べるだけ） |
| `commit-map.txt` | 反映のたびに書き出される、本体のコミット番号 → 公開用の番号の対応表 |

同じ規則・同じコミットからは、毎回同じコミット番号の写しができます。だから2回目からは、新しいコミットが増えるだけ（早送り）です。

## 止まったとき

- `the rules changed the current files too`：本体の今のファイルに、規則に引っかかるものが残っている。本体で直して push してから、もう一度。
- `… thing(s) left in the copy`：過去の版に残っているもの（言葉そのものは表示しません。ファイルと行と、どの決まりかだけ）。`replace-text.txt` に置き換えを足す。
- `the public main is not part of the new copy`：規則を変えたので、前に公開した写しとつながらなくなった（その箇所から後のコミット番号が全部変わる）。公開用を作り直す（force-push）かどうかは作者が決める。すでに公開した部分に効く規則は、できるだけ足さない。
- `… not noreply ones`：新しいメールアドレスのコミットが入った。`mailmap.txt` に足す（この Mac は `git config --local user.email` を noreply にしてあるので、普段は起きない）。

## コミット番号

公開記録・README などの文書に書いてあるコミット番号は、**本体（非公開）の番号**です。公開用では番号が違います。公開サイトの `/release.json` の番号も本体のものです。公開用での番号は、`public-mirror/commit-map.txt` で引けます。
