# カット割りの部品の考え方（部品作りの前に読む）

STUDIO の「✂ カット割り」は、歌詞の1行を短いカット（0.5〜1.5秒）に割り、カットごとに**軸ごとの部品**を1つずつ選んで重ねる。部品は軸ごとに独立に選ばれるので、**1つ足すと、ほかの軸の全部の部品と組み合わさる**。部品の数は足し算、表現の数は掛け算で増える。同じ理由で、**事故も掛け算で増える**（下の「4. 組み合わせで壊れる」）。

この文書は、作者と Claude が 2026-10-16〜18 に部品を 103 個から 189 個まで増やした時の考え方をまとめたもの。毎日の部品作り（`docs/daily-samples-routine.md` の ③）は、これに沿って進める。作る部品の候補は `docs/cut-parts-wishlist.md`。

## 1. 言葉（軸と動きの型）

**軸**（いつ・何として起こるか）。画面の名前と、コードのキー:

| 軸 | 日本語 | 何に・いつ | キー |
|---|---|---|---|
| IN | 登場 | 字が出てくる時 | `enter` |
| STAY | 保持 | 字が居る間ずっと | `hold` |
| OUT | 退場 | 字が消える・去る時 | `exit` |
| STYLE | 字の描き方 | 字そのものの見た目 | `treat` |
| DECO | 飾り | 字の周りに足す飾り | `deco` |
| BG | 背景 | 字の後ろの絵 | `bg` |
| CAM | カメラ | 文字の層全体を動かす | `cam` |
| FX | 画面効果 | できた絵に後から掛ける（カットの頭） | `fx` |
| TRANS | つなぎ | カットとカットの切り替わり | `trans` |
| STAGE | 文字を載せる台 | 字を物の上に置く・2つ以上が絡む構図 | `world` |

**動きの型**（どう動くか。軸をまたぐ）: 移動・拡縮・回転・透明／点滅・ぼけ・切り抜き・字送り／順番・分解／粒・変形・振動／ずれ・色／光・線／描画・図形／模様・漂う物・字の見た目・台／枠 の16種。同じ「拡縮」が IN（ポップ）にも STAY（呼吸）にも CAM（ズームパンチ）にもある。

迷った時の物差し:
1. いつ起こるかで IN・STAY・OUT が決まる（同じ「バウンド」でも、出る時なら IN、居る間なら STAY）。
2. 何に起こるかで、文字・画面全体・カットの間が分かれる（文字だけなら IN〜DECO、絵ごと動かすなら CAM、後から掛けるなら FX、切り替わりなら TRANS）。
3. 2つ以上が絡む動きや、物の上に置くのは STAGE。
4. 形容詞は STYLE、動詞は IN か OUT。
5. 字そのものを変えるのは STYLE、周りに足すのは DECO。
6. ふんわりした言葉（「衝突」）は1つの部品ではなく、何軸かの組み合わせ（IN のドン ＋ CAM のズームパンチ ＋ FX の揺れ）。

「部類」という言葉は使わない。軸の下の段は「動きの型」。

## 2. 見本の読み方（作るものを決める）
1. **読む**: 何が（字・語・行・画面全体・カットの間）、いつ（出る時・居る間・去る時・カットの頭・切り替わり）、どう（動きの型）を拾う。長さ・緩急・字ごとか語ごとかも。
2. **分ける**: 軸 → 動きの型 → 部品。1つの見本は、ふつう何軸かの組み合わせ。
3. **当てる**: 今の部品で出せるか（◎）、近いが芯がないか（○）、ないか（＋）。曲の拍に合わせる話・曲の区間ごとに作りを替える話は、部品より上の段なので別。
4. **まとめる**: 「＋」「○」のうち、同じ部品で何件もまかなえるものから作る。順番は「**すぐ作れる × 当たる見本が多い**」。重いもの（書き順の線描・粒の融合・本物の3D）は後回し。
5. **作る**: その軸の手本（今ある部品）と同じ形で、自分の式で書く。他の作品のコード・文・素材は写さない。部品の名前・説明は自分の言葉で。

## 3. エンジンにある道具（2026-10-18 の時点。部品からそのまま使える）
字の部品（IN・STAY・OUT）の `glyph(...)` が返せる値（`glyphs.js` の `stateAt` が合成する）:

| 値 | 何か | 手本 |
|---|---|---|
| `dx` `dy` `sx` `sy` `rot` `a` `blur` `hide` | 位置・大きさ・回転・不透明度・ぼけ・隠す | ほとんどの部品 |
| `ch` | その字の代わりに描く字（記号・伏せ字など）。置き換え中は「読めない」と数えられる | `enter/scramble` `maskReveal` `hold/glyphSwap` |
| `reel: {cur, next, u}` | 字の枠で切り抜き、2つの字をリールのように縦にずらして描く | `enter/slotReel` |
| `cell: true` | 字の元の位置の枠で切り抜いてから動かす（枠の外は見えない） | `enter/maskRise` `maskSlideX` `exit/maskExitUp` |
| `paint: {u, color}` | 字の左から u の割合を別の色で塗り直す（`color:'accent'` でアクセント色） | `hold/paintSweep` |
| `bold` | 字と同じ色の縁で太らせる（字の大きさに対する割合、0.08 くらいまで） | `hold/weightBreathe` `weightWave` |
| `thin` | 細い輪郭だけで描き、塗りを薄くする（1 で輪郭だけ） | `enter/thinToBold` |
| `erode` | 字が境目から削られて消え、削れた所が粒になって飛ぶ `{kind:'sand'|'burn'|'rub',k,…}`（k は削れの進み。1 で全部削れ、1 を過ぎても粒は飛ぶ。読めない状態として数える） | `exit/sandAway` `burnAway` `rubAway` |

`item(it,p,E,P)` が書ける値: `blur` `sx` `sy` `a` `clip`（左右の切り抜き）`bar`、`split: {ang, n, t, dy, line}`（文字の中心を通る斜めの線で上下を切り分ける。手本 `enter/splitIn` `exit/splitDrop`）。

STYLE（`treat`）の `style()` が返せる値: `stroke` `fill` `shadow` `extrude` `textColor` `deco`（`'marker'` `'underline'` `'box'`）`blur` `trail`、`fillFx: {kind:'rainbow'|'shine'|'stripes', …}`（字の塗りそのものが時間で動く。手本 `treat/rainbowFill` `shineSweep` `stripeFill`）、`longShadow: {ang,swing,v,len,color}`（字から長く伸びる影。光の向きが時刻で振れる。手本 `treat/longShadow`）、`echo: {n,dx,dy,color}`（輪郭だけのコピーをずらして重ねる。手本 `treat/echoOutline`）、`rim: {w,color}`（`stroke` の外側のもう1本のフチ。手本 `treat/doubleRim`）。

STAGE（`world`）: `arrange(item,P)` で字の位置（`g.cx` `g.cy` `g.rot0` `g.size`）を並べ直せる（並べ直したら `item.bbox` も作り直す。手本 `ringText` `spiralText` `shapeText`）。`knockout: true` と `plate(c,e,P,{mask})` で、画面いっぱいの板に字の形の穴を開ける（手本 `knockout`…）。`frame()` が `size`（字の大きさ px）と `fit: false` を返すと、字を箱に収めずにその大きさで置く（はみ出した所は絵の外で切れる。手本 `megaText`）。

毎日の部品は `daily-parts.js` だけで書く（本体は変えない）ので、ここにない道具が要る部品は作らずに、ログの「次に作れそうなこと」に「⚙ 本体に〜の仕組みが要る」と書く。

## 4. 組み合わせで壊れる（実際に起きた事故）
部品1つだけを見ていると見つからない。どれも 2026-10-18 に直した。

- 画面いっぱいの板（抜き文字）× 写真の上の「反転」→ 反転が「描いてある所に白を重ねる」作りだったので、板が真っ白になった。→ 本当の色の反転に。
- 明るい大きな面（抜き文字の板・帯重ね・吹き出し・つなぎで残る前のすりガラス）×「ブルーム」（足し算の光）→ 白く飛んだ。→ 絵の平均の明るさで弱める。
- 白いアクセント色の配色 × 板がアクセント色 → 画面いっぱいの白い板。→ 白に近い時は紙の色に。

だから、**面で覆う部品**（STAGE・DECO の板・BG の大きな光）や、**足し算・反転で色を変える部品**（FX）を作った日は特に、ゲートの「組み合わせの総当たり」（下）の結果をよく見る。落ちたら、メッセージに出る部品の組み合わせから原因を探す（どちらの部品が悪いかは、片方ずつ外して描けば分かる）。

## 5. 確かめ方
1. 単体テスト（`node --test tools/test/studio/*.test.mjs`）: 形・名前・計画が選ぶか・保存した値が範囲に収まるか・登場は元の形で終わるか…
2. プレビューの絵を開いて見る（`docs/daily-samples-routine.md` の 3）: 動きの途中が写っているか、字が読めるか。
3. ゲート（`node tools/verify_daily.mjs --expect-new=<今日>`）:
   - 部品ごと: 本物のエンジンで描け、動き、読め、下に絵がある時に塗りつぶさない。
   - **組み合わせの総当たり**: 計画を40通り（下に写真あり・なし）作って全コマを描き、絵の7割以上が白に近いコマがないか。
4. 計画の種で結果が変わるテストは、1回通っただけで安心しない。1回でも落ちたら、原因が分かるまで「直した」と言わない。
